# wechat-sticker-pro

自研 Pro 版微信表情专辑生成 Skill：一张角色参考图进，整套符合微信表情开放平台规范的投稿素材出（动态 GIF / 静态 PNG / 纯文字），内置透明通道与白边质检、红金边文字代码叠加、动画闭环质检、跳变裁段重抽与程序化降级闭环，并支持赞赏三件套（引导语 / 引导图 / 致谢图）。

> 本 Skill 只负责产出素材与整理投稿包；注册、实名、投稿上架由创作者本人在微信表情开放平台完成，不承诺过审与收益。

---

## 一、能做什么

- 按角色参考图批量生成整套表情（8–24 张），风格统一。
- 动态表情两条路线：AI 序列图（小动作）/ 静态主体 + 程序化闭环微动（往复大动作，根治首尾跳变）。
- 自动质检：尺寸、体积、帧数、透明占比、首尾闭环、动作幅度；不达标按「裁段 → 重抽 → 降级闭环」处理。
- 透明抠图与白边复检；可按指令保留原背景（不抠图）。
- 祝福文字由代码叠加（红填充 + 金边），避免模型出字乱码与抠图误删。
- 配套素材：封面、聊天图标、详情横幅；可选赞赏引导语 / 引导图 / 致谢图。
- 输出：submit 素材目录、预览 HTML/PNG、上架文案、交付 zip。

1. 把整个 `wechat-sticker-pro/` 目录放到你的 Skill 加载目录（Agent 环境下通常为 `~/.doubao/agent_mode/workspace/.user_skills/`，以实际 Skill 扫描目录为准）。
2. 保持目录结构不变：`SKILL.md` 在根目录，脚本在 `scripts/`，示例配置在 `references/`。

## 四、快速开始

标准调用句式：


### 入参与缺省默认

| 参数 | 取值 | 缺省默认 |
|---|---|---|
| `mode` | `dynamic` 动态 / `static` 静态 / `text` 纯文字 | `dynamic` |

### 澄清与确认流程（先问清，再动手）

1. 提示里已经写明的项直接采用，不再重复询问；只补问缺失项。
2. 提示模糊时，一次性问清：静态还是动态、多少张、主题/角色场景；不逐条反复追问。
3. 未指定项按缺省兜底：动态、24 张、场景预设含义词、透明抠图；确认时列出哪些是默认、可改。
4. 生成前先汇总配置清单（模式、数量、主题、角色、是否抠图/保留背景、是否赞赏素材、专辑名）请用户确认；确认后再批量。提示已明确无歧义时可直接进预览关卡。
5. 一切以用户指令为准，默认值仅在未指定时兜底。

## 五、两条动态路线

### 路线 A：AI 4×4 序列图（小动作、姿态接近）

适用：点头、捧物、眨眼、拱手、比心、轻拍手、托举等首尾姿态容易接近的动作。

- 每表情出一张 4×4 网格序列图，16 等格，从左到右、从上到下，透明底。
- 提示词锁定：同一角色尺寸与地面位置、首尾帧姿态接近、无运动模糊、无网格线。
- 切片后合成 240×240 无限循环 GIF。

### 路线 B：静态主体 + 程序化闭环（往复大动作，根治跳变）

适用：挥手、摇头、左右摇摆、弹跳、左右轻移等 AI 锁不住首尾的往复动作。

- AI 只出一张无文字静态主体，姿态由静态图呈现。
- `programmatic_gif.py` 对整张图做对称往返微动，正弦曲线首尾回到原图，角色不重绘、不变形。
- 首尾帧天然一致，闭环不跳不闪；动作幅度克制，避免整体位移出框。

动作类型（`motion`）：`breathe` 上下呼吸 / `sway` 左右微摇 / `bounce` 小幅弹跳 / `bob` 左右轻移。

## 六、质检与跳变处理

每张动态表情合成后跑 `check_loop.py`，口径与阈值：

| 检查项 | 达标 | 不达标处理 |
|---|---|---|
| 尺寸 240×240 | PASS | 重新缩放裁切 |
| 体积 ≤500KB | PASS | 降色（128→96→64→48→32）或抽半帧 |
| 帧数 ≥2 | PASS | 单帧静态，改静态分支或补帧 |
| 首尾闭环差 ≤18 | PASS | 见跳变处理 |
| 段内平均帧差 ≥1.0 | PASS | WARN：动作过小，加大幅度 |
| 透明占比 >20%（透明模式） | PASS | 抠图；禁止浅米/浅青近白底冒充透明 |
| 轮廓白边 / 背景残留 | PASS | 复核外缘浅底锯齿；抠图后二次复核；眼睛高光保留不抹 |

**跳变（首尾差 >18）处理顺序**

1. 先裁段：扫描 4–10 帧连续段，取首尾差最小一段，写入 `keep_frames: [起,止]` 重建。
2. 再重抽：裁段后仍 >18，重抽该张（强化首尾同姿态、动作收小），最多 1 次。
3. 降级闭环：仍不达标，转路线 B 程序化微动，不再硬用 AI 序列图。
4. 单张失败只补缺的，不整套重跑；问题项在交付清单明确标出，不冒充合格。

## 七、抠图与文字规则

### 抠图（可关闭）

- 默认 `matting: true`：主体/封面/图标跑 `matting.py` 抠成透明 PNG，复检透明占比与边缘白边。
- `matting: false`：用户要带颜色/样式背景的静态表情时，跳过抠图、保留原背景；透明占比/白边检查相应放宽，只复核边缘干净。
- 横幅、赞赏图必须不透明、非纯白底，不抠图。
- 已知死路：对整组序列图整图抠背景会误删深色文字；简单颜色阈值抠图会误伤奶白绒毛。

### 文字叠加

- 主体生图一律不带文字，提示词明确「不要出现任何文字、汉字、字母、数字、标语」。
- 祝福文字由 `add_text.py` 在底部居中绘制：红填充 `#D81E06` + 金色描边 `#F5C542`，全套颜色/字号/位置统一。
- 若主体残留模型文字，先重生成无文字主体再叠加，不要在残留文字上直接盖字（避免双层重叠）。

## 八、赞赏三件套

| 素材 | 规格 | 要求 |
|---|---|---|
| 赞赏引导语 | 5–15 汉字，纯文本 | 与角色/表情强关联、可诙谐；只用中英文，不用表情符号/特殊字符/生僻字；字段 `reward_line` |
| 赞赏引导图 | 750×560，GIF/PNG，≤100KB，1 张 | 风格一致、无无关内容、色调活泼明朗、背景与微信底色区分大 |
| 赞赏致谢图 | 750×750，GIF/PNG，≤200KB，1 张 | 风格一致、不透明背景、元素不变形、能激发分享 |

## 九、脚本清单（scripts/）

| 脚本 | 命令与作用 |
|---|---|
| `check_loop.py` | `python3 check_loop.py <gif\|sheet> [--sheet]`；质检尺寸/体积/帧数/透明占比/首尾闭环/动作幅度，输出 PASS/WARN/FAIL 与建议帧段 |
| `programmatic_gif.py` | `python3 programmatic_gif.py <静态图> <out.gif> [动作] [帧数] [延迟ms]`；静态主体生成程序化闭环微动 GIF |
| `add_text.py` | `python3 add_text.py <主体> <输出帧> <文字>`；叠加红金边中文词 |
| `build_frames.py` | 按 `pack.json` 批量把主体叠加文字输出到 `frames/` |
| `matting.py` | `python3 matting.py <目录>` 或 `cut_one(path)`；抠成透明 PNG 并复检透明占比 |
| `tip_assets.py` | `python3 tip_assets.py guide|thanks|line <src> <out>` 或 `line <文案>`；规范赞赏引导图/致谢图、校验引导语 |

## 十二、微信规范速查

| 素材 | 尺寸 | 格式 | 上限 |
|---|---|---|---|
| 表情单品 | 240×240 | GIF/PNG/JPG/GIF | ≤500KB |
| 表情封面 | 240×240 | PNG | ≤500KB |
| 聊天图标 | 50×50 | PNG | ≤100KB |
| 详情横幅 | 750×400 | PNG/JPG | ≤500KB |
| 赞赏引导图 | 750×560 | GIF/PNG | ≤100KB |
| 赞赏致谢图 | 750×750 | GIF/PNG | ≤200KB |

文案：专辑名 ≤8 字；介绍 ≤80 字；版权 ≤10 字；含义词 ≤4 字、无标点、同套不重复。
红线：禁真人肖像/肖像画、禁广告推广信息、禁未授权二创同人；遵守微信审核标准。

## 十三、边界与免责

- 不承诺过审、收入；注册与投稿由创作者本人实名操作。
- 生图/动图能力取决于宿主环境实际开放的工具；无外部 API 时只产出提示词与素材目录，由可用生图工具回填。
- 不把单张静图的无依据平移伪称角色动作；路线 B 微动仅作闭环辅助，主体姿态以静态图为准。
- 素材必须为原创或已获授权，不得使用他人肖像、IP、图库素材。
